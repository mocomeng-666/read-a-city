# 生图服务接入说明

用户配置自己的 API Key 后，Skill 用 `scripts/gen_image.py` 直接生成全景，不必手动去别的工具。

**当前状态（2026-11-03）**：五家的调用代码已写好，演练模式和本地假服务器测试都通过。**万相已用真实 Key 调用 7 次，都成功**，其余四家还没有真实调用过。全景的提示词写法已定为 `panorama-prompt-template.md` 的模板（2026-11-03 写入 Skill）。

**万相首次调用（永平，无字提示词，两张参考图）**：一次成功，用时 19.9 秒，返回 1152×2048 PNG，按官方单价约 0.2 元。无字要求完全做到，放大检查招牌也是空白；纸色和淡彩风格对。**构图没有跟参考图**：河变成横向，还多出一条河道；石桥成了占满下半幅的近景，只画了四五孔；矿场是裸露的橙色台阶，不是复绿的灰绿；老房子偏多、红墙多，比实际更像古镇。编号牌靠手动对位还能放上去，但只能当氛围图。

**万相第二次（v2）**：只给一张无字的代码版全景，构图要求放最前，提示词缩短到约 500 字，开头写“严格保持参考图的构图”。15.0 秒，约 0.2 元。结果走到另一头：几乎是参考图的描摹，梯形地块、方块房子、点状小树都照搬，只把红点换成了小楼和亭子、把矿山画成绿色梯田，不像手绘插画；桥画得很小，一半架在岸上。好处是位置和代码版一致，编号牌直接用 `panorama.marks.json` 就能对上。

**两次的结论**：万相对参考图要么几乎不管（v1，两张图、长提示词），要么几乎照抄（v2，一张图、“严格保持”）。

**万相第三次（v3）**：仍是一张无字草图，提示词开头先说要画什么插画，再说“参考图只是布局草图，只借位置关系，梯形边界、方块房子、点状树都不要出现，画面铺满”。17.8 秒，约 0.2 元。**基本可用**：像手绘插画，没有文字（放大查过教学楼和招牌）；一条宽河斜向右上、左下有小溪汇入，五孔石桥带亭子在下方三分之一，城墙沿老城一侧河岸，正中一小片灰瓦平房围着小亭，镇上是白墙居民楼。不足：教学楼画成七八层；矿山像梯田；廊桥画在田野里，方位和实际（镇东）不符；远处多出一段河。编号牌手动对位，见 `county-yongping/source/panorama-ai-v3.marks.json`。

**经验**：参考图是代码草图时，开头先描述成品，再明确说“参考图只是布局草图、只借位置关系”，并点名草图里不要出现的元素；不要写“严格保持构图”。

**万相第四次（v4）**：针对 v3 的四个问题逐条写明（教学楼“只有四层，不比居民楼高多少”；矿山“一圈圈开挖台阶长满草，不是梯田”；廊桥“左下小溪上、靠近石桥左端、带顶”；河“到中部偏右就隐入房后，远处不再出现”）。18.4 秒，约 0.2 元。四点全部改好，无字。新问题：报本坊小亭没画（v3 有）；矿山占了左上四分之一，比实际显眼，部分台阶是裸土。经验：逐条点名缺陷有效，但改一处可能丢另一处，每版都要按全部检查项重看。四次合计约 0.8 元。

**改用模板（3 个锚点）之后**：见 `panorama-prompt-template.md`。永平一次成功，沙井换成轻量草图后一次合格；三次约 0.6 元。逐条调提示词的做法不再推荐。至此万相共 7 次，约 1.4 元。

## 选型硬条件

1. 支持参考图（图生图）。全景靠代码版构图图定位道路和编号，只能文字生图的模型不合格。
2. 能输出竖版 9:16，或接近的比例（叠加页按 1080×1920 裁切填满）。
3. 服务条款允许这样使用，用户所在地区能开通和付费。产品主要面向中国大陆，国内服务优先。

## 怎么用

1. 复制 `image.example.json` 为 `image.local.json`（已在 `.gitignore` 里），选好 `provider`，按需改型号、尺寸、单价。
2. Key 放环境变量（推荐），或填进 `image.local.json` 的 `api_key`。Key 不贴进对话。
3. 先演练，拿到地址、参数和预计费用，报给用户：

   ```bash
   python3 -I scripts/gen_image.py --prompt <城市>/01-panorama-codex-prompt.md \
     --ref <城市>/images/01-panorama-code.png --ref <城市>/images/03-walk-map.png \
     --out <城市>/images/01-panorama-ai.png
   ```

4. 用户同意后，同一条命令加 `--send`。成图旁边会写一个 `.gen.json`，记下服务商、型号、用时和提示词指纹（不含 Key）。
5. 按提示词文件里的检查表核对，合格后对位编号牌，用 `overlay.py <config> <成图> <out.html> <marks.json>` 叠加标题、路名、编号牌和图例，再截图出最终图卡。

## 用手机上的生图 App（没有 Key 时首选）

给自己和身边人用时，最短的路是借用户手机上已有的生图 App，不走 API。

1. **整理提示词**：用 `panorama-prompt-template.md` 或历史场景的写法，生成一段完整的中文描述，去掉 Markdown 和代码块，直接发给用户。历史场景不需要参考图；全景要借位置关系时，让用户把轻量草图一起发进 App。
2. **告诉用户怎么做**：打开豆包、即梦或 ChatGPT，粘贴这段话；如果能选比例，选竖版 9:16；生成后挑一张最好的存下来，发回给我。
3. **交回后检查**：
   - 资料里写到的人、物、行当是否都在；
   - 有没有可读的假字；
   - 有没有不该出现的现代物件；
   - 建筑外观是否被画成了某处真实地标。
   不合格的话，请用户在 App 里让它“重画一张”，最多一两次。
4. **做成图卡**：用 `scene_card.py` 或 `overlay.py` 加标题、标签和“示意”说明，标签可以盖住假字。App 自带的“AI 生成”水印保留，不裁掉。

各 App 的免费额度、出图比例和水印规则会变，以 App 里的说明为准。这一档还没用真实用户走过一遍，第一次用时记下哪一步卡住。

## 规则

- **Key 不进对话。** 不写进交付文件、日志和仓库；脚本从不打印 Key。
- **先报价后调用。** 不加 `--send` 不会发请求。告诉用户服务商、张数和预计费用，得到同意才加 `--send`。重试要再问一次，默认最多两次。
- **模型只画画，字由代码加。** 用计费 API 时用无字提示词（全景见 `panorama-prompt-template.md`，场景画见 `scene-prompt-template.md`）：不写任何字、不画编号牌，顶部和底部留白。`panorama.py` 会写出 `.marks.json`（编号牌和路名的位置，取自代码版全景），`overlay.py` 带上这个文件时加标题、路名和编号牌；看过成图后在副本里微调位置。Codex 版提示词仍让模型写字，两条路并存。
- **不支持或没配 Key 时不中断。** 交付代码版全景和提示词，继续后面的流程。
- **内容口径不变。** 提示词只描述画面，不写未经证实的历史判断（比如永平“膽泉”与宋代胆水的关系只是推想，提示词里不提）。
